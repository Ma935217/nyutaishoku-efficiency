## 3. 管理者が次に行う手順（Windows）

### 手順1：動作確認（約10分）

1. `届出作成ツール_v1.1.xlsm` を、Googleドライブの同期フォルダなど、仕事用の場所に移す（ダウンロードフォルダに置いたままにしない）。
2. 開き直して、帯が出たら「コンテンツの有効化」を押す。
3. 「出力」シートに［チェック］［CSV出力］のボタン、「入職台帳」「退職台帳」に［台帳をクリア］のボタンがあることを確認する。
4. 「出力」シートの届種別で「社保取得」を選び、［チェック］を押す。「対象 3 件／エラー 0 件／警告 2 件」のような表示が出ればよい（ダミーのグエンさんは基礎年金番号がなく警告が出る）。
5. ［CSV出力］を押し、確認画面で「はい」。xlsmと同じ場所の `出力` フォルダに、`社保取得_日付_時刻` というフォルダができ、中に `SHFD0006.CSV` が入る。
6. 届種別を「社保喪失」「雇保取得」「雇保喪失」にして、同じ操作をする。社保喪失はCSV（ダミー1名）、雇保は「内容確認」シートに転記一覧ができる。

### 手順2：仕様チェック（届書作成プログラム Ver.34.00）

1. 届書作成プログラムを開き、起動メニューの「仕様チェック 社会保険(S)」を押す。
2. 手順1で作った `SHFD0006.CSV` が入っているフォルダを指定してチェックする（フォルダに他のファイルを置かない）。
3. エラー0件なら、取得・喪失の両方で同じ確認をする。
4. エラーが出たら、メッセージ（項目名）を記録して、新しいセッションのClaudeに貼る。レイアウト定義シートを直す。
5. 両方エラー0件になったら、設定シートの「届種別一覧」で社保取得・社保喪失の「確定」を「済」にして、変更履歴シートに記録する。

### 手順3：実値の入力とダミーの消去

1. 設定シートの黄色い値を実際の値にする：事業所記号（半角カナ）、郡市区符号、事業所番号、事業所の郵便番号・所在地・電話、法人名、事業主氏名、媒体通番（前回の続き）、雇保事業所番号。都道府県コードは長野県＝37（確認すること）。
2. 「入職台帳」「退職台帳」で［台帳をクリア］を押し、ダミーデータを消す。
3. 「内容確認」シートの内容を消し、「ログ」のテスト記録を消すか残すか決める。
4. 上書き保存する。

### 手順4：共有サーバへの配置（管理者が行う。Claudeは共有サーバに書き込まない）

1. 共有サーバの人事フォルダに、アクセスできる人を絞った `届出作成ツール` フォルダを作る。
2. `届出作成ツール_v1.1.xlsm` と、運用手順書（Word）を置く。`出力` フォルダは、ツールが自動で作る。
3. 担当者のPCごとに、Excelの「信頼できる場所」にこのフォルダを登録する（運用手順書 第2章）。
4. 担当者に運用手順書で説明し、実案件で1か月運用して、ヒアリングシートの作業時間を再記入してもらう。

### 手順5：残りの確認（任意・後日）

- Windowsで確認する項目W1〜W12（テスト記録）。特に、機種依存文字「髙」で漢字氏名が省略されて警告が出ること、CSVをメモ帳で開いて半角カナが文字化けしないこと。

## 4. 新しいセッションのClaudeへ（技術メモ）

### 設計の要点

- マクロは `modExport` 1本。項目の並び・固定値・コード値・条件はシート上の表（レイアウト定義、コード表、設定、ルール）に持つ。仕様変更ではマクロを直さない。
- 台帳（入職・退職）は3区画：自動列、追加入力（黄色）、DB貼り付け欄（入退職管理マスタの行を値で貼る。見出しの改行・★は無視して照合）。
- レイアウト定義の取得元：`台帳:列名`／`設定:名前`／`システム:今日`／`固定`／`空欄`。変換は `半角カナ`、`漢字氏名`、`年金上4`・`年金下6`、`郵便上3`・`郵便下4`、`電話1`〜`3`、`コード表:区分`、`翌日`、`空なら0` など。条件は `=`、`<>`、`~`（含む）、`|`（または）。必須は `○`（エラー）、`△`（警告）。
- 社保のファイルは、媒体管理・`[kanri]`・事業所数・事業所情報・`[data]` の5行（ヘッダー1〜5）に続けて、届書データ（明細）を並べる。取得届と喪失届は別ファイル（別フォルダの `SHFD0006.CSV`）。媒体通番は出力ごとに自動で進む。
- マイナンバーは持たない（個人番号の欄は空欄）。基礎年金番号と住所を出す。

### 作り直しと試験

```bash
python3 "tools/届出作成ツール/build_tool.py"
```

```bash
python3 "tools/届出作成ツール/test/lo_test.py" /tmp/届出試験
```

- 試験はLibreOfficeのVBA互換モードで18項目。LibreOfficeでは Shift_JIS 判定が使えないため、試験用フラグ `gSkipSjis` で省いている。
- VBAを直したら、原本（`modExport_utf8.bas`）を直し、`build_tool.py` で `modExport.bas` を作り直す。管理者はVBEで古い `modExport` を削除してから取り込み直し、`SetupButtons` を再実行する。
- 管理者が運用を始めたブック（実値入り）を、`build_tool.py` の出力で上書きしない。

### 落とし穴（実際に起きたこと）

- VBAは大文字小文字を区別しない。モジュール変数 `mId` は組み込みの `Mid` と衝突した。変数名は組み込み関数と重ならないようにする。
- LibreOfficeでは、変数名 `base` が予約語でコンパイルできない。
- クラウド環境から年金機構のサイトは開けない。仕様書は管理者がGitHubにアップロードしたPDFを読む（Markdownや画像の変換はpdftotextで可能）。

### 守ること

- 共有サーバ（`\\` で始まる場所）は、承認なしに閲覧・書き込み・移動をしない。
- 実在の個人情報・マイナンバーをリポジトリや試験に入れない。ダミーデータだけを使う。
- 削除・送信など取り消せない操作の前は、内容を要約して確認する。
- プルリクエストは、管理者が頼んだときだけ作る。
