## 1. 目的・トリガー

- 届出担当者が共有サーバ上のExcelブック1本を開き、ボタン操作だけで次の2つを得られるようにする。
  - **機能A**：入退職者1名ごとの「届出チェックリスト」（必要な届出・提出先・期限日）。数式のみ。
  - **機能B**：日本年金機構「届書作成プログラム」に取り込めるCSV（社保 資格取得届／喪失届、雇保 資格取得届／喪失届）。VBAマクロ1本。
- 本書は「実装してほしい」と依頼されたとき、または計画書の段階1〜3に着手するときに読む。

### 2.2 動作環境

- Windows 10/11＋Microsoft 365 Apps（Excel）。FILTER・XLOOKUP・LET が使える前提。
- 共有サーバのフォルダに `.xlsm` を置き、各PCから開く。同時に開いた2人目は読み取り専用（許容）。
- 届書作成プログラムは担当者PCにインストール済みとする。

### 2.3 開発環境（実装モデル側）

- 実装はWindows＋Excelで行うのが望ましい。クラウド環境（Linux）で作る場合は `openpyxl` でシート・数式・入力規則・書式を作り、VBAは `.bas` テキストで納品して、Windows側で VBE から「ファイルのインポート」をしてもらう（手順は第10章）。`openpyxl` は既存のVBAプロジェクトを保持できないため、**VBAを含むファイルの再保存はWindows側でのみ行う**。
- 数式は英語名（`IF`, `FILTER`, `EOMONTH`…）で書く。日本語の関数名は存在しない。

### 5.6 レイアウト定義（機能Bの中核。コードを変えずに仕様に追従するための表）

1行＝CSVの1項目。届種別ごとに連番で並べる。

| 列 | 内容 | 値の例 |
| --- | --- | --- |
| 届種別 | 社保取得／社保喪失／雇保取得／雇保喪失 | 社保取得 |
| 行種別 | ヘッダー／明細（仕様書にヘッダー行や事業所行があれば使う） | 明細 |
| 順番 | CSV内の項目順（1始まり） | 7 |
| 項目名 | 仕様書の項目名をそのまま | 被保険者氏名（カナ） |
| 取得元 | `台帳:列名`／`設定:名前`／`事業所:列名`／`固定` | 台帳:氏名（カナ） |
| 固定値 | 取得元が固定のときの値（レコード識別子など） | （仕様書の値） |
| 書式 | 文字／数値／日付8（YYYYMMDD）／和暦7（元号コード+YYMMDD）／和暦分割（元号・年・月・日を別項目にする場合は項目を分ける） | 和暦7 |
| 桁数 | 最大桁。超えたらエラー | 25 |
| 必須 | ○／空 | ○ |
| 変換 | `全角カナ`／`半角`／`コード表:区分名`／空 | 全角カナ |
| 条件 | この項目を出す条件（例：`外国籍=有`）。空なら常に出す。不成立なら空欄で出す | 外国籍=有 |
| 備考 | 仕様書のページ番号など | p.12 |

**埋め方の手順**（実装モデルが行う）

1. 仕様書の「資格取得届」レコードレイアウト表を開き、項目を上から順に転記する（項目名・桁数・必須・書式）。
2. 取得元を台帳の列名に対応付ける。対応する列がなければ台帳に列を追加する（勝手に省略しない）。
3. コード値がある項目は「コード表」に区分を作り、変換列に `コード表:区分名` と書く。
4. 日付の表記（西暦8桁か、元号コード付きか）を仕様書で確認し、書式列に反映する。
5. 4種分を埋めたら、「順番」が1から欠番なく並んでいることを `COUNTIF` で確認する数式をシート右上に置く。

### 5.7 出力シート（担当者の操作画面）

- セル `B3`：届種別（プルダウン：社保取得／社保喪失／雇保取得／雇保喪失）。
- ボタン1「チェック」：出力対象○の行を検証し、エラー一覧を `A10` 以下に出す（行番号・職員番号・項目名・内容）。ファイルは作らない。

- 出力後、ファイル名と件数をセルとメッセージボックスで表示する。
- ボタンは**フォームコントロール**（ActiveXは使わない）。

### 5.9 ルールシート（判定ルール表）

列：No／届出名／届出先／場面（採用／退職／両方）／条件列14本／基準／加算方式／日数／作成方法／備考／**該当（数式）**／**期限日（数式）**。

- 条件列（14本）：社保・雇保・外国籍・特定技能・扶養・70歳以上・59歳以上・特徴・共済・役職・離職票・退職金・障害者・解雇。セルが空＝問わない、「有」＝その条件が「有」のときだけ該当。
- 該当の数式（1行目に書いて下にコピー）：
  `=AND(OR([@場面]="両方",[@場面]=入力区分), OR([@社保]="",入力社保="有"), OR([@雇保]="",入力雇保="有"), …14本同様…)`
  入力側は名前付き範囲（`入力区分`、`入力社保`…）で参照する。70歳以上・59歳以上・解雇は入力欄から数式で「有／無」に変換した補助セルを使う。
- 期限日の数式：
  `=IF([@該当], IF([@加算方式]="日数", 基準日+[@日数], IF([@加算方式]="翌月10日", EOMONTH(基準日,0)+10, IF([@加算方式]="翌月末", EOMONTH(基準日,1), IF([@加算方式]="1か月後", EDATE(基準日,1), "")))), "")`
  基準は「基準日」「基準日翌日」「なし」の3種。基準日翌日は `基準日+1` を使う。
- 初期ルール（第7章の表）をそのまま入れる。期限は保守的に「事実発生日＋日数」とし、備考に「前日までの提出を目標」と書く。

## 6. マクロ仕様（VBA）

### 6.1 方針

- 標準モジュール1本 `modExport.bas`。150〜250行を目標。クラスモジュール・ユーザーフォーム・ActiveX・外部参照設定（Microsoft Scripting Runtime 等）は使わない。
- `Option Explicit` 必須。`Select`／`Activate` は使わない。シートは `ThisWorkbook.Worksheets("名前")` で参照する。
- 失敗時は必ず「何行目の何がダメか」をエラー一覧とログに残し、ファイルは作らない。

### 6.2 手続き一覧

| 名前 | 種類 | 役割 |
| --- | --- | --- |

| `btnExport` | Public Sub（ボタン） | `ValidateRows` → 0件なら `WriteCsv` → `WriteLog` → 台帳に出力済日時を書く |

| `ValidateRows(kind, rows, layout)` | Private Function | 必須・桁数・日付妥当性・コード表に存在・Shift_JISで表せる文字か・出力済の二重出力を検査し、エラー件数を返す |

### 6.3 処理の流れ（`btnExport`）

1. 出力シートの届種別を読む。空なら「届種別を選んでください」で終了。
2. `GetLayout`：レイアウト定義で該当届種別の行を「順番」で並べ替えて配列化。0行なら「レイアウト定義がありません」で終了。
3. `GetTargetRows`：台帳の出力対象○の行を集める。
4. `ValidateRows`：1件でもエラーなら出力シートに一覧を書き、`MsgBox "エラーがn件あります。修正してから再実行してください"` で終了（ファイルは作らない）。警告（IBM拡張文字など）は一覧に出すが続行可。
5. ヘッダー行（行種別＝ヘッダー）があれば先に1行作る。明細は対象行ごとに `BuildLine`。
6. 出力フォルダがなければ作る（`MkDir`）。`WriteCsv`。
7. 台帳の出力済日時に `Now` を書く。`WriteLog`。
8. `MsgBox "n件を出力しました：" & path`。

### 6.4 コードの書き方（壊れにくさのための約束）

- 列は**見出し名で探す**（1行目を `Match` で検索）。列を挿入されても動くようにする。
- 「順番」の欠番・重複はチェックで検出し、エラーにする。
- 日付セルは `IsDate` で確認してから `CDate`。文字列の `2026/11/1` も受ける。
- `Asc` の戻り値は2バイト文字で負になる。`If code < 0 Then code = code + 65536`。
- `On Error GoTo` は各ボタン手続きの先頭に1つ。捕捉したら `Close` を確実に行い、ログに「異常終了：Err.Description」を書いてメッセージを出す。
- `Application.ScreenUpdating` 以外のアプリ設定は触らない。
- 日本語のシート名・名前付き範囲を使ってよい（担当者が読めることを優先）。

### 6.5 Shift_JIS と引用符

- 仕様書が「文字コードShift_JIS・引用符なし」なら `Print #` で十分。値にカンマや改行が含まれていたらエラーにする（引用符で逃がさない）。
- 仕様書が引用符ありを要求する場合は設定シートの `引用符` を「する」にして全項目を `"` で囲む。

### 6.6 雇用保険が届書作成プログラムで作れない場合の代替

- 届種別「雇保取得（転記用）」「雇保喪失（転記用）」を追加し、CSVではなく「転記用一覧」シート（ハローワークインターネットサービスの入力順に並べた表）を印刷する。レイアウト定義の仕組みはそのまま使い、出力先がシートになるだけ。

## 8. CSVレイアウトの作り方（仕様書との突合）

1. 日本年金機構サイトから「届書作成プログラム」の最新版と、仕様書（CSVファイルのレイアウトが載っているもの）をダウンロードする。
2. 仕様書の「資格取得届」のレコードレイアウトを、レイアウト定義シートに**順番どおり**転記する（第5.6節の手順）。
3. 仕様書の「使用できる文字」「日付の表記」「引用符」「文字コード」「ヘッダーレコードの有無」を設定シートに反映する。
4. ダミー1件でCSVを作り、届書作成プログラムの取込機能で読み込む。エラーメッセージが出たら、その項目のレイアウト定義を直す（コードは直さない）。
5. エラー0になったら、プログラム側の「届書内容の確認」画面または印刷で、台帳の値と1項目ずつ照合する。
6. 喪失届・雇保取得届・雇保喪失届も同じ手順で行う。
7. 外国籍の職員は社保の「ローマ字氏名届」が別途必要になる場合がある。仕様書で取込対応の有無を確認し、非対応ならチェックリスト側に「ローマ字氏名届（紙）」の行を追加する。
