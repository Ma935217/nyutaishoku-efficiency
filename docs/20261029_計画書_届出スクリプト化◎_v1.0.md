## 1. 結論（先出し）

1. **作るもの**：Excelブック1本「届出作成ツール」（マクロ入り `.xlsm`）。共有サーバの人事フォルダに置き、届出担当者が開いて使う。
2. **やること**：ヒアリングシートで◎と仮判定した5件を、次の2機能にまとめる。
   - **機能A 届出チェックリスト自動生成**（No.25）：入職／退職・国籍・扶養・年齢・役職などを入れると、必要な届出と期限日を一覧化する。**マクロ不使用（数式のみ）**。
   - **機能B 届書作成プログラム用CSV出力**（No.1・4・5・6）：台帳の行から、日本年金機構「届書作成プログラム」に取り込めるCSVを作る。社保の資格取得届・喪失届、雇用保険の資格取得届・喪失届の4種。**小さなマクロ1本**。
3. **やらないこと**：電子申請の「送信」、マイナンバーの保持、MJS給与システムへの書き込み、他の○△届出。
4. **進め方**：4段階（準備→機能A→機能B→定着）。機能Aは数式だけなので最初に出して効果を見せる。機能Bは社保取得届から着手し、残り3種は同じ仕組み（レイアウト定義シート）の差し替えで作る。
5. **壊れにくさの設計**：マクロは「CSVを書き出す」1本だけ。項目の並びや固定値は**シート上の定義表**に持たせ、仕様変更時にコードを触らずに直せるようにする。入力は入力規則（プルダウン）で縛り、出力前に必須チェックを通す。
6. **実装への引き継ぎ**：同フォルダの「実装手順書」に、シート構成・列定義・マクロ仕様・テスト手順・納品物を記載済み。実装モデル（Opus）はそれに従って作る。

## 2. 背景と目的

- 法人規模は職員約780名、年間の入退職は150名前後。社保・雇保の取得届・喪失届は「PC入力→印刷→郵送／持参」で、1件15分前後かかっている（ヒアリングシートの担当者記入値）。
- ヒアリングシートの事務局仮判定で◎は5件。いずれも「共通データ（氏名・生年月日・入退職日など）から機械的に作れる」ものである。
- 既存の効率化案では「GビズID取得→届書作成プログラムで電子申請→将来はPSD労働社会保険（有償）」の流れを示している。本計画はその**無償・短期の中間解**であり、PSD等を導入した時点で機能Bは役目を終える（出口戦略）。
- 入退職管理マスタは別計画で「入職DB・退職DB（各1シート）」への統合が進行中。本ツールの入力はその**入職DB・退職DBからのコピー**を前提にする（同じ列名に揃える）。

## 4. 方式の選定

| 方式 | 担当者の使いやすさ | 壊れにくさ | 配布・保守 | 判定 |
| --- | --- | --- | --- | --- |
| Excel＋小さなVBA（採用） | ◎ Excelを開くだけ | ○ 定義表方式でコード変更を最小化 | ◎ 共有サーバに1ファイル | **採用** |
| Python スクリプト | △ 各PCにPython導入が必要 | ○ | △ IT部門の手配が要る | 不採用 |
| Power Automate Desktop | △ 画面操作の自動化は壊れやすい | × | △ | 不採用 |
| 数式のみ（マクロなし） | ◎ | ◎ | ◎ | **機能Aに採用**。CSV書き出しは数式では不可 |

採用理由：担当者の環境は Windows＋Microsoft 365（Excel）で追加導入なし。マクロは「CSV書き出し」1本に限定し、判定ロジックや項目定義はすべてシート上に置く。

## 7. 安全・個人情報の扱い

- ツール本体（`.xlsm`）には**実在職員のデータを入れたまま保存しない**。台帳シートは「入力→出力→クリア」で使い、出力CSVは共有サーバのアクセス制限フォルダに置く。提出後の保存期間は担当者と決める（仮：提出月の翌月末まで）。
- マイナンバーはツールに入れない（第6章#4）。共通ルール第3条レベル1に該当。
- GitHubリポジトリに置くのは、ダミーデータ入りのサンプルと文書のみ。実データ入りファイルは置かない。
- 削除・上書きの自動処理は作らない。出力CSVは毎回新しいファイル名（日時付き）で作る。

## 8. リスクと対策

| リスク | 対策 |
| --- | --- |
| 共有サーバ上のマクロがブロックされる | 各PCで「信頼できる場所」に当該フォルダを登録（運用手順書に記載）。登録できない場合はローカルコピーで実行し、出力だけサーバへ |
| 届書作成プログラムの仕様変更でCSVが通らない | レイアウト定義シートを直す。コード変更不要の設計 |
| 氏名の外字・環境依存文字で取込エラー | 出力前チェックで警告。最終判定は届書作成プログラム側の取込チェックに任せる |
| 担当者がマクロを怖がる | ボタンは2つだけ（「チェック」「CSV出力」）。処理内容はログシートに残す |
| 作る人と使う人が違い、保守できなくなる | 実装手順書に「変更するときはここだけ」を明記。コードは1モジュール・150行以内を目標 |
