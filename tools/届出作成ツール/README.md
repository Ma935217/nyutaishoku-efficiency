# 届出作成ツール v1.0（実装物）

入退職時の届出チェックリストと、社保・雇保の届書データを作るExcelツール。
設計は `docs/20261029_計画書_届出スクリプト化◎_v1.0.md`、仕様は同 `実装手順書`、担当者向けの使い方は `docs/20261029_運用手順書_届出作成ツール_v1.0.md`。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `届出作成ツール_v1.0.xlsx` | マクロなしのブック（ダミーデータ入り）。Windowsでマクロを取り込んで `.xlsm` にする |
| `vba/modExport.bas` | VBEで取り込むファイル（Shift_JIS・CRLF）。**直接編集しない** |
| `vba/modExport_utf8.bas` | マクロの原本（UTF-8。GitHubで読める）。直すのはこちら |
| `build_tool.py` | ブックと `modExport.bas` を作り直すスクリプト |
| `test/lo_test.py` | LibreOfficeでの自動試験（Windows Excelでの最終確認の前の予備試験） |

## Windowsで完成させる手順（初回のみ・約10分）

1. `届出作成ツール_v1.0.xlsx` と `vba/modExport.bas` を自分のPCの作業フォルダにコピーする。
2. Excelで `届出作成ツール_v1.0.xlsx` を開き、`Alt+F11` でVBE（マクロの編集画面）を開く。
3. VBEのメニュー「ファイル」→「ファイルのインポート」で `modExport.bas` を選ぶ。左の一覧に「標準モジュール → modExport」が出ればよい。
4. VBEのメニュー「デバッグ」→「VBAProject のコンパイル」を押す。何も表示されなければ成功。
5. VBEを閉じ、Excelで `Alt+F8` →「SetupButtons」→「実行」。出力シートに［チェック］［CSV出力］、各台帳に［台帳をクリア］のボタンが付く。
6. 「名前を付けて保存」→ ファイルの種類「Excel マクロ有効ブック (*.xlsm)」→ `届出作成ツール_v1.0.xlsm` で保存する。
7. 動作確認：出力シートで「雇保取得」を選び［チェック］→［CSV出力］。内容確認シートにダミー3名の転記一覧が出ればよい（社保は下の「CSV仕様の確定」が済むまでエラーになるのが正常）。
8. 各台帳の［台帳をクリア］でダミーデータを消し、設定シートの黄色欄を実際の値に差し替えて保存する。
9. 共有サーバの人事フォルダに置き、各担当者PCで「信頼できる場所」を設定する（運用手順書の第2章）。

## CSV仕様の確定（社保取得・社保喪失を使えるようにする）

このクラウド環境から日本年金機構のサイト（www.nenkin.go.jp）に接続できず、CSV仕様書を確認できなかった。そのため、次の値は**未確定**で、社保のCSV出力は「届書コードが空」のエラーで止まるようにしてある。

1. 日本年金機構「届書作成プログラム」のページから、最新の「CSV形式届書作成仕様書（健康保険・厚生年金保険適用関係届書）」を入手する。
2. レイアウト定義シートの「社保取得」「社保喪失」を仕様書と1項目ずつ突き合わせる。
   - 届書コード（レコード識別子）を「固定値」に入れる
   - 項目の順番・桁数・全角／半角・日付の表し方（和暦7か、元号と年月日を分けるか）
   - ファイル全体のヘッダー行（事業所情報など）があれば、行種別「ヘッダー1」「ヘッダー2」…で追加
   - ファイル名が決まっていれば設定シートの届種別一覧「ファイル名」に入れる
3. コード表のCSVコード（性別・被扶養者・備考・喪失原因など）を仕様書の値で確認する。空欄の行（社保喪失備考）を埋める。
4. 設定シートの文字コード・引用符を仕様書に合わせる。
5. ダミー1名でCSVを出力し、届書作成プログラムで読み込んでエラー0件になることを確認する。
6. 確認できたら設定シートの届種別一覧の「確定」を「済」にし、変更履歴に記録する。
7. 雇用保険も届書作成プログラムのCSV読込に対応していれば、同様にレイアウトを作り「出力形式」をCSVに変える。

> 次回この作業をClaudeに任せる場合は、クラウド環境のネットワーク設定（Allowed domains）に `www.nenkin.go.jp` を追加すると、仕様書を直接読んで定義表を埋められる。

## 作り直し・試験（開発者向け）

```bash
python3 "tools/届出作成ツール/build_tool.py"
```

```bash
python3 "tools/届出作成ツール/test/lo_test.py" /tmp/届出試験
```

- `build_tool.py` はダミーデータ入りの初期状態を作る。**運用開始後のブック（実値入り）を上書きしないこと。** 運用後の修正はブック側で行い、マクロを直したときは原本（UTF-8）を直して `build_tool.py` で `modExport.bas` を作り、VBEで古いモジュールを削除してから取り込み直す。
- LibreOfficeの試験では Shift_JIS 判定（機種依存文字の警告）とUTF-8書き出しは確認できない。Windows Excelで確認する（テスト記録の「Windowsで確認する項目」）。
